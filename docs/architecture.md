# Архитектура

## Решение

Система строится как модульный монолит. Это снижает сложность первого запуска, но сохраняет строгие границы модулей и позволяет позднее вынести real-time, аналитику или интеграцию с 1С в отдельные сервисы.

Поток данных: `React UI → REST/WebSocket API → прикладные сервисы → Prisma → PostgreSQL`.

## Модули backend

- Auth, Users, Roles — идентификация и права.
- WorkCenters — справочник участков и назначения сотрудников.
- Orders, OrderItems — заказы, позиции, цены и частичная готовность.
- Procurement — готовность закупки, сроки и риск.
- ProductionLaunches — частичные и повторные запуски заказа.
- Routes — заданные Планером шаги и зависимости без автоматического определения технологии.
- Operations, TimeTracking — задачи участков, статусы, остановки и фактическое время.
- Notifications — проблемы и оперативные сообщения Планеру.
- Planning, Analytics — сроки, загрузка и агрегаты.
- Integrations — изолированный слой импорта и будущего mapping 1С.
- Audit — неизменяемая история критических действий.

## Доступ

Планер обладает полным рабочим доступом. Сотрудник участка получает только операции участков, к которым он привязан. Ограничение применяется в backend-запросах; скрытие элементов в UI является лишь дополнительной мерой.

## Real-time

После подтверждённой транзакции backend публикует доменное событие. Socket.IO доставляет его только в комнаты разрешённых участков и отдельную комнату Планеров.

## Развёртывание

Один Windows/Linux-сервер в локальной сети: reverse proxy, web, api и PostgreSQL. Для роста API остаётся stateless; сессии и Socket.IO adapter можно перенести в Redis.
